# PR #303 review round — OTel bootstrap crate refinements

**Date:** 2026-06-03 09:15:00
**Branch:** `feat-issue-295-otel-bootstrap-crate`
**PR:** #303 (OTel observability Phase 1)

Addresses the eight inline review comments on review #119. Each change is a
standalone additive commit mapping 1:1 to a comment, so the reviewer can
re-review per thread.

## Changes

1. **Drop unused `thiserror`** from `crates/sandbawks-observability/Cargo.toml`
   — all errors flow through `anyhow::Result`.
2. **Structured config warnings.** Replace the `Vec<String>` deferred-warning
   channel with a `ConfigWarning { env_var, value, message }` struct; each is
   replayed as a structured `tracing::warn!` event (greppable by `env_var`,
   survives JSON log routing) instead of a pre-`format!`'d string.
3. **Honor `OTEL_EXPORTER_OTLP_TIMEOUT`.** Parse the spec millisecond value once
   and thread an `Option<Duration>` through all three exporter builders via a
   generic `apply_timeout` helper (both protocol arms implement
   `WithExportConfig`). Unparseable values warn and fall back to the SDK
   default rather than failing startup.
4. **Seed `service.instance.id`.** From the K8s downward-API `POD_NAME`, falling
   back to a per-process random UUID off-cluster, so multi-replica deployments
   are distinguishable. Seeded before the env merge so an operator's
   `OTEL_RESOURCE_ATTRIBUTES` still wins. Adds `uuid` (`v4`) to the workspace.
5. **Implement `OTEL_DEBUG_STDOUT`.** When truthy, attach a synchronous stdout
   span processor alongside the OTLP batch one (OTLP throughput untouched).
   Adds `opentelemetry-stdout` 0.32 (`trace` only) to the workspace, pinned on
   the same OTel line. Factored the truthy-env check into a shared `env_truthy`
   helper reused by `otel_sdk_disabled`.
6. **Enrich the disabled-path startup line** with `service_version` and an
   explicit `endpoint=disabled`, making it shape-comparable with the active
   path.
7. **Document the OTLP-log trace-id correlation gotcha** in `install_subscriber`
   — logs *look* correlated in stderr (fmt layer) but ship with no
   `trace_id`/`span_id` on the OTLP side until the Phase 3 `TraceContextLogBridge`.
8. **Document the kube-startup vs export-timeout ordering** at the
   `init_telemetry` call site in `sandbawks-api` (the first exporter is built
   before `Client::try_default()` resolves credentials).
