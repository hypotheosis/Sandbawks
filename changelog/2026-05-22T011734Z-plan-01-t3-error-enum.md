  `InvalidQuantity` variant's `Display` impl.

## Out-of-scope fixes (necessary to make T3's acceptance test runnable)

T2 left the crate in a deliberately uncompilable state — `lib.rs`
referenced six modules that don't exist yet, and the workspace pinned
`k8s-openapi 0.24` while `kube 0.97` transitively pulls in `0.23`,
causing the `0.23` build script to panic ("None of the v1_* features
are enabled"). Without addressing both, the T3 acceptance test
(`cargo test -p sandbawks-types --test smoke error_display_renders`)
cannot compile, let alone pass.

The three minimum fixes applied here:

1. `Cargo.toml`: `k8s-openapi = 0.24` → `0.23` so the version aligns
   with what `kube 0.97` brings in transitively. Only one version of
   `k8s-openapi` remains in the tree, and its `v1_31` feature is
   enabled.
2. `crates/sandbawks-types/src/lib.rs`: trimmed module declarations and
   re-exports to `error` only. Later T4–T8 each add back their own
   `pub mod …;` + `pub use …;` line as they create the module.
3. `crates/sandbawks-types/Cargo.toml`: removed the `[[bin]] crdgen`
   stanza (the binary file doesn't exist yet — T9 creates it).

These changes are incremental and reversible by later tasks; nothing
that T2 set up has been semantically discarded.
