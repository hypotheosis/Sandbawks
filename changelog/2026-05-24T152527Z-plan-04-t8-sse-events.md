# Plan 04 T8 — SSE event stream endpoints

Date: 2026-05-24T15:25:27Z
Issue: gfd/sandbawks#107 (Plan 04 epic #99)

## Scope

Adds two server-sent-events endpoints on the gateway:

| Method | Path                            | Stream content                                  |
|--------|---------------------------------|-------------------------------------------------|
| GET    | `/events/sandboxes`             | All `involvedObject.kind == "Sandbox"` events in the team's namespace |
| GET    | `/events/sandboxes/:id`         | Same, narrowed to one sandbox id                |

Each delivered frame is `data: <json>\n\n` where the JSON shape is
`{ type, reason, message, sandboxID, timestamp }` — a deliberate
projection of `k8s_openapi::api::core::v1::Event` down to the five
fields the E2B SDK consumes.

## What changed

- `crates/sandbawks-api/src/routes/events.rs` — replaced the
  one-line placeholder with the full implementation:
  - `EventDTO` (`#[derive(Serialize)]`) with explicit
    `#[serde(rename = "type" / "sandboxID")]` so the wire shape matches
    the E2B SDK byte-for-byte.
  - `ev_to_dto(K8sEvent)` — projection, with a defense-in-depth check
    that drops `sandboxID` if the involved-object kind isn't `Sandbox`.
  - `event_matches(&K8sEvent, Option<&str>)` — kind/name filter pulled
    out as a free function so it's trivially unit-testable.
  - `watch_events(api, filter_sandbox)` — spawns a background task that
    drives `kube::runtime::watcher(...).applied_objects()` through a
    bounded `tokio::sync::mpsc::channel(64)`. Drops watcher errors
    silently (watcher auto-restarts; we don't want a transient
    apiserver hiccup to terminate the SSE connection). Breaks out of
    the loop when `send` fails so a disconnected client promptly stops
    the upstream watch.
  - `stream_all` / `stream_one` handlers wrap the returned stream in
    `axum::response::sse::Sse` with
    `KeepAlive::new().interval(Duration::from_secs(15))`.
  - `router(state)` mounts both routes behind `auth_middleware`, using
    the same `Arc::clone(&state.key_store)` pattern as
    `routes::sandboxes` so the middleware state and handler state line
    up cleanly.
  - Three unit tests in a `#[cfg(test)] mod tests` block:
    `ev_to_dto_renders_e2b_shape`,
    `ev_to_dto_drops_sandbox_id_when_kind_mismatch`,
    `event_matches_filters_by_kind_and_name`. They cover the
    projection and filter logic without needing a watcher.

- `crates/sandbawks-api/tests/events.rs` — new smoke test crate:
  - `missing_auth_is_unauthorized` — `GET /events/sandboxes` without
    `X-API-Key` → 401.
  - `missing_auth_on_single_route_is_unauthorized` — same for
    `/events/sandboxes/:id`. Confirms the middleware is wired for both
    routes, not just the list path.

  Full event delivery against a real apiserver is covered by T15's
  kind integration test; standing up a watcher under
  `AppState::for_test`'s 204-returning mock service would just hang.

- `crates/sandbawks-api/src/bin/sandbawks-api.rs` — merged
  `routes::events::router(state.clone())` into the top-level `Router`
  alongside the existing `routes::sandboxes::router` merge.

## Why the 15s keepalive

K8s Ingress and most cloud LBs idle-close TCP connections at 60s.
A 15s SSE keepalive comment-frame keeps the connection warm with
plenty of margin, while a quiet sandbox burns only ~4 frames/minute.

## Why drop watcher errors

`kube::runtime::watcher` is bookmark-aware and auto-reconnects on
apiserver hiccups. Propagating the error to the SSE consumer would
break the connection and force the SDK to reconnect, defeating the
whole point of the watcher's resilience. The continue-on-error in
`watch_events` keeps the stream open across transient failures.
