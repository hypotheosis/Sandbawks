# Chore — drop chart-bundled CRDs; manage them out-of-band

## Why

Every time the CRD schema changed, the chart's vendored copy under
`deploy/helm/sandbawks/crds/` drifted from the canonical
`deploy/crds/`, breaking the helm-CI parity check (`diff -ru`). The
fix was always "remember to `cp deploy/crds/*.yaml
deploy/helm/sandbawks/crds/`", which is exactly the kind of footgun
that wants a structural fix rather than discipline.

Compounding the issue: Helm 3 doesn't upgrade chart-managed CRDs on
`helm upgrade` (see [Helm chart best practices][helm-crds]). The
bundled CRDs were therefore actively misleading — they made it look
like the chart owned CRD lifecycle when in practice operators had to
re-apply them manually anyway.

[helm-crds]: https://helm.sh/docs/chart_best_practices/custom_resource_definitions/

## What

- **Removed** the entire `deploy/helm/sandbawks/crds/` directory
  (4 YAML files) along with the
  `diff -ru deploy/crds deploy/helm/sandbawks/crds` parity step in
  `.forgejo/workflows/ci.yml`. The canonical source remains
  `deploy/crds/`, regenerated by `cargo run -p sandbawks-types --bin
  crdgen -- deploy/crds`.
- **Updated install workflow** in `justfile` (`cluster-up`) and
  `.forgejo/workflows/kind-smoke.yaml` (both `helm install` steps) to
  `kubectl apply -f deploy/crds` first, then `helm install --skip-crds`.
- **Documented** the new pattern in `docs/kind-smoke.md` with a short
  rationale + the two-line install snippet, linking the Helm docs that
  recommend this pattern.
- **Path-filtered the Rust CI gate.** Added a `detect-changes` job to
  `.forgejo/workflows/ci.yml` (using `dorny/paths-filter@v3`) that
  gates the `rust` (fmt/clippy/test/doc) and `crd-yaml-up-to-date`
  jobs on whether the PR touches Rust-affecting paths (`**/*.rs`,
  `**/Cargo.toml`, `Cargo.lock`, `**/*.proto`, `rust-toolchain*`,
  `.cargo/**`, the CI workflow itself, and `deploy/crds/**`). The
  `helm` job continues to run unconditionally. Chart/docs/CI-only
  PRs like this one now skip ~10 min of Rust validation that
  couldn't have caught anything anyway. Image builds + kind-smoke
  are intentionally left alone (separate workflow, matrix-parallel +
  sccache-cached, not the long pole).

## Operator migration

Anyone running an existing `helm install sandbawks` from this chart
needs a one-time change to their install command:

```diff
+ kubectl apply -f deploy/crds
- helm install sandbawks deploy/helm/sandbawks [--set ...]
+ helm install sandbawks deploy/helm/sandbawks --skip-crds [--set ...]
```

Existing clusters already have the CRDs (the previous chart did
install them on `helm install`), so this is forward-compatible — the
`kubectl apply` becomes a no-op on already-current CRDs.
