## Summary

Plan 07 closes the runtime-side resume gap that Plan 05 left open
(#176): `runsc restore`
rejects a kubelet-managed container because it is already `running`, never in
the `stopped`/`created` state the restore command requires. The fix is a
custom containerd runtime shim, `containerd-shim-sandbawks-v1`, that links
gVisor's `pkg/shim/v1` packages as a Go library and drives the restore *from
inside* the standard kubelet → containerd → shim Create/Start flow, so the
container is born already restored and the lifecycle never has to be inverted.

After Plan 07, a `gvisor` sandbox pauses (`runsc checkpoint`, S3 upload —
unchanged from Plan 05) and resumes end-to-end against a kubelet-managed Pod
on a kind cluster: the controller stages the snapshot bundle to a node, then
creates a fresh Pod under the additive `RuntimeClass: sandbawks-runsc` carrying
an `io.sandbawks/restore-image-path` annotation; the shim turns that annotation
into a `runsc restore`. The `pause-resume-smoke.sh` smoke runs
`PAUSE_RESUME_SMOKE_FULL=1` by default again, and the perf bench runs with
`BENCH_INCLUDE_RESUME=1`, both green on `main`.

**One locked decision changed during implementation.** Plan §"Architectural
decisions locked" §1 specified driving gVisor's `CreateWithFSRestore` +
`Restore` extension RPCs so the *filesystem* is restored from the checkpoint
image at create time. Bringing that path up against a real cluster
(T8–T11 + #230) showed the FS-restore graft was racy and unnecessary: the
sandbox's writable state already lives on an overlay-backed rootfs that the
fresh Pod re-materializes, so only the *memory* image needs restoring. PR #234
dropped the `CreateWithFSRestore` graft and simplified the shim to a
**memory-only** `runsc restore`. The shim, the annotation contract, the
staging pipeline, and the `sandbawks-runsc` RuntimeClass all stand as planned;
only the restore RPC the shim dispatches changed. The fs-checkpoint seam
analysis that produced this pivot is recorded in #231 (issue #230).

## What landed (per task)

- **T1 — `shim/` Go subtree scaffold** (#218, issue #205). First Go code in an
  otherwise all-Rust repo: module `github.com/hypotheosis/sandbawks/shim`, a runnable
  stub binary, a `just shim-build` recipe, and CI plumbing. The Rust workspace
  neither builds nor links the subtree; the shim ships as a standalone binary
  in the node image.
- **T2 — pass-through TaskService decorator** (#219, issue #206). A `Service`
  struct wrapping gVisor's `extension.TaskServiceExt`, forwarding all ~17
  standard task RPCs plus the two extensions straight through. gVisor pinned to
  the same release (`20240603.0`) baked into `sandbawks-kind-node`, so the
  extension RPC surface matches the runtime on the node. Table tests assert
  every method calls through to a recording fake.
- **T3 — Create-time annotation dispatch** (#220, issue #207).
  `parseRestoreAnnotation` reads `io.sandbawks/restore-image-path` from the OCI
  spec and (originally) dispatched `Create` → `CreateWithFSRestore`; an in-shim
  `sync.Map` keyed by container ID remembers restore intent for the matching
  `Start`. Rejects relative / non-existent paths (staging-root escape defense).
- **T4 — Start-time dispatch to Restore** (#221, issue #208). `Start` →
  `Restore` for containers flagged in T3's map, threading the remembered image
  path. `RestoreConfig.Background=false` (synchronous) — the documented seam
  for Plan 08's lazy/page-fault restore, with a one-line comment marking it.
- **T5 — bake the shim into the kind-node image** (#222, issue #209). A
  `shim-builder` stage in `ci/kind-node/Dockerfile` `go build`s the binary to
  `/usr/local/bin/containerd-shim-sandbawks-v1`, and a new
  `containerd-sandbawks-runsc.toml` registers runtime handler
  `sandbawks-runsc` (`runtime_type = io.containerd.sandbawks-runsc.v1`,
  discovered on `$PATH` by name). Appended to `/etc/containerd/config.toml`
  the same way Plan 05 appended the runsc handler (kind's config has no
  `imports`, so `conf.d/` drop-ins are silently ignored).
- **T6 — `RuntimeClass: sandbawks-runsc` Helm template** (#223, issue #210).
  `runtimeclass-sandbawks-runsc.yaml` gated by `.Values.sandbawksRunsc.enabled`
  (default true). Additive — the Plan 05 `gvisor` RuntimeClass stays for
  non-sandbawks workloads.
- **T7 — `SnapshotJobMode::Stage` + `status.localPath`** (#224, issue #211).
  New PascalCase-tagged `Stage` enum variant (no `rename_all` — that would
  break already-deployed `Pause`/`Resume` resources) and an
  `Option<String> localPath` status field, plus a default `stage_snapshot`
  trait method. CRDs regenerated; crdgen golden still idempotent.
- **T8 — `GvisorAdapter::stage_snapshot`** (#225, issue #212). Downloads the
  snapshot bundle from S3 to
  `/var/lib/sandbawks/staging/<sandbox-id>/<job-uuid>/`, verifies per-part
  sha256 as bytes land, and unpacks the `memory.zst` tar+zstd into the
  `checkpoint.img` / `pages.img` / `pages_meta.img` layout `runsc restore
  --image-path` expects. The shared unpack is factored into one private helper
  both `stage_snapshot` and the (now fallback-only) `resume` call, so the
  layout has exactly one definition.
- **T9 — split `Action::Resume` into Stage + CreateRestorePod** (#226, issue
  #213). State machine gains `Action::StageSnapshot`, `Action::CreateRestorePod`,
  and `Trigger::StageComplete`; `(Resuming, PodReady) → Running` is now terminal
  (the container is born restored, so there is no post-create SnapshotJob step).
  `pod_adapter` defaults the restore Pod's `runtimeClassName` to
  `sandbawks-runsc`, sets the `io.sandbawks/restore-image-path` annotation, and
  pins `spec.nodeName` to the staging node. No `hostPath` volume and no
  `SANDBAWKS_RESTORE_MODE` env injection.
- **T10 — deprecate `SANDBAWKS_RESTORE_MODE`** (#227, issue #214). envd logs a
  "deprecated, removed in Plan 08" warning on entry when the env var is set;
  behavior otherwise unchanged. Kept for one release as the controller's
  fallback when the shim isn't installed.
- **T11 — `PAUSE_RESUME_SMOKE_FULL=1` default; assert shim path** (#229, issue
  #215). `pause-resume-smoke.sh` defaults the resume round-trip back on, made
  tri-state (`1` = shim path with restore-annotation assertion, `0` = skip
  resume as before, `legacy` = the deprecated RESTORE_MODE path) so existing
  `=0` configs keep their skip semantics.
- **T12 — workspace green gate + enable resume bench + this changelog** (#246
  for the bench flip, this PR for the summary; issues #196 + #216).
  `.forgejo/workflows/kind-smoke.yaml` flips `BENCH_INCLUDE_RESUME` `0` → `1`
  on the bench job; #196 closed with a pointer to #246. See "Resume perf gate"
  below for the threshold change.

## Resume bring-up hardening (surfaced once CI actually ran a restore)

Turning the gates on exposed gaps the unit tests could not — these landed as
follow-ups under epic #204 and are part of "Plan 07 resume actually works":

- **Memory-only restore; drop the `CreateWithFSRestore` graft** (#234, issue
  #232). The pivot described in the Summary, validated by a large-overlay spill
  test (#233) showing memory-only restore holds at scale.
- **Fail-closed teardown** (#239, issue #235). The controller validates that a
  restore succeeded (storage round-trip proof) *before* tearing down the source
  Pod, so a failed resume cannot strand a sandbox with no recoverable state.
- **envd rootfs fingerprint** (#240, issue #236). envd hashes its rootfs at
  pause and re-verifies after restore, catching a rootfs/memory-image mismatch.
- **Mount-set assertion at pause** (#241, issue #237). Every writable mount must
  be overlay-backed at checkpoint time, or pause fails closed — the invariant
  the memory-only restore depends on.
- **Resource-headroom policy** (#242, #244, issues #238/#243). Pause and restore
  are gated on node disk and memory headroom; #244 tightened the memory gate to
  key off the *uncompressed* `pages.img` size so a large restore can't OOM the
  node.
- **Controller-owned stale-Pod delete + `gvisor` → `sandbawks-runsc` mapping**
  (in #246). `CreateRestorePod` deletes the `Succeeded` pre-pause Pod before
  creating the restore Pod (previously the smoke did this by hand with
  `kubectl delete`; the bench and real E2B clients could not), and `pod_spec_for`
  maps the cold-start `gvisor` class onto `sandbawks-runsc` for the restore Pod.
  Both make resume work for a `gvisor` sandbox end-to-end without external pod
  surgery.
- **Tracing to stderr** (#245, issue #228). `sandbawks-node`/`controller`/`api`
  route tracing to stderr, aligning with envd so CI log capture is consistent.

## Resume perf gate (6500 ms CI tripwire, not the spec target)

With resume working, the bench measured resume p95 ~5.2 s on the 16 MiB CI
workload — over spec §13's 2 s ceiling. That ceiling assumes *lazy/page-fault*
restore (`RestoreConfig.Background`), which is **Plan 08**. Plan 07's restore is
*eager*: it materializes the whole memory image before the container runs, so
resume is dominated by roughly payload-independent fixed overhead (stage
download, stale-Pod teardown, Pod create, shim `runsc restore`, envd boot).
`BENCH_RESUME_P95_MS` in `kind-smoke.yaml` is therefore set to `6500` — a
regression tripwire with headroom over the observed ~5.2 s, **not** the spec
goal. `DEFAULT_RESUME_P95_MS` in `tests/bench/src/main.rs` stays `2000` as the
documented §13 target; the CI override carries a comment to tighten it back when
Plan 08's lazy restore lands.

## What's deliberately not here (Plan 08+)

- **Warm pool** (`SandboxWarmPool` reconciler + claim path). Depends on the
  working resume this plan delivers. Plan 08.
- **Lazy / page-fault restore** (`RestoreConfig.Background=true`). The seam is
  the T4 `RestoreConfig` literal; flipping it is the lever that brings resume
  p95 toward the spec §13 2 s target. Plan 08.
- **`SANDBAWKS_RESTORE_MODE` *removal*.** Deprecated in T10 (#227), deleted in
  Plan 08 — kept one release so #171's contract isn't broken in the same
  release that obsoletes it.
- **`runsc checkpoint` replacement.** The shim's standard Task `Checkpoint` RPC
  is `errdefs.ErrNotImplemented` upstream, so pause stays on the Plan 05 +
  #195 direct shell-out. Revisit only if upstream gVisor wires Checkpoint
  through the shim.
- **`CreateWithFSRestore` filesystem restore.** Removed in #234 as racy and
  unnecessary given overlay-backed rootfs; would only return if a future
  runtime lacks the overlay re-materialization the memory-only path relies on.
- **Kata-fc** — Plan 09. **runc-criu** — Plan 10 (or deferred past v0.1).
