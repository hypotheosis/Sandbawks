# Issue #387 — Stamp git SHA on all OTel traces, metrics, and logs

**Date:** 2026-06-07T22:17:30Z
**Issue:** #387 — encode git SHA into built artifacts and surface via OTel
**Type:** feature (`kind/feat`, `area/observability`, `area/deploy`)

## Background

Telemetry could not be tied back to the build it came from. The OTel
`Resource` carried `service.version` (always `env!("CARGO_PKG_VERSION")`, i.e.
the workspace `0.1.0`) and a per-replica `service.instance.id`, but **no git
revision**. That made the central question — "was this error already fixed on a
newer commit?" — unanswerable from a trace, metric, or log alone.

## Design

The telemetry stack is already fully centralized: all four binaries
(`sandbawks-controller`, `sandbawks-api`, `sandbawks-node`, `envd`) call the
shared `sandbawks_observability::init_telemetry`, which builds **one** OTel
`Resource` (`build_resource`) shared by the tracer, meter, and logger
providers. So a single resource attribute propagates to every signal of every
binary with no per-call-site work.

The git SHA is captured at **build time** and stamped as the OTel VCS
semantic-convention attribute `vcs.revision`.

### SHA resolution (priority order)

A new `crates/sandbawks-observability/build.rs` resolves the SHA, first non-empty
wins:

1. `SANDBAWKS_GIT_SHA` build-time env var — injected by CI / the Docker
   `--build-arg GIT_SHA=...`. The image build context excludes `.git` (see
   `.dockerignore`), so this is the **only** source that resolves in-image.
2. `git rev-parse HEAD`, suffixed `-dirty` when the working tree is dirty — the
   local `cargo build` path.
3. The sentinel `"unknown"` — a missing SHA never fails the build.

It emits `cargo:rustc-env=SANDBAWKS_GIT_SHA=<value>` plus
`rerun-if-env-changed=SANDBAWKS_GIT_SHA` and (when a git dir is present)
`rerun-if-changed=<git-dir>/HEAD`, so a local rebuild re-stamps when HEAD moves
without forcing a rebuild on every invocation.

### Stamping

`init::build_resource` gains one `.with_attribute(KeyValue::new(VCS_REVISION,
vcs_revision()))`, seeded **before** the detected-attribute merge (mirroring
`service.instance.id`) so an operator's
`OTEL_RESOURCE_ATTRIBUTES=vcs.revision=...` still wins. `vcs_revision()` reads
the build-time `option_env!("SANDBAWKS_GIT_SHA")`, collapsing absent/blank to
the `unknown` sentinel so the attribute is never empty.

## Changes

- `crates/sandbawks-observability/build.rs` — **new**; resolves and exports the
  SHA as a compile-time env var.
- `crates/sandbawks-observability/src/init.rs` — `VCS_REVISION` /
  `BUILD_GIT_SHA` / `UNKNOWN_REVISION` consts, the `vcs_revision()` helper, the
  new resource attribute, and two unit tests
  (`resource_carries_vcs_revision`, `vcs_revision_falls_back_to_unknown_sentinel`).
- `crates/{sandbawks-controller,sandbawks-api,sandbawks-node,envd}/Dockerfile` —
  `ARG GIT_SHA=unknown` + `ENV SANDBAWKS_GIT_SHA=$GIT_SHA` in the builder stage
  (where the observability build script runs).
- `.forgejo/workflows/kind-smoke.yaml` — pass `GIT_SHA=${{ github.sha }}` to the
  `build-images` matrix build-args, so published images stamp the real commit.

## Validation

- `just fmt` — clean.
- `cargo clippy --all-targets -- -D warnings` — clean.
- `just test` — full workspace green; the two new observability tests pass.
- Local build: confirmed `bcc8ace...-dirty` (current HEAD) baked into the rlib.
- Injection path: `SANDBAWKS_GIT_SHA=deadbeefcafe cargo build` baked
  `deadbeefcafe` in, proving the CI/Docker build-arg overrides the git fallback.

A full `docker build` of the images was not run here (the cargo-chef + musl +
sccache CI flow is heavy and pulls the the private registry ci-runner base); the in-image
SHA source (the `SANDBAWKS_GIT_SHA` env var) was exercised directly via the
injection-path build above.

## Review follow-up (PR #394)

- **build.rs HEAD-watch bug:** `rerun-if-changed=<git-dir>/HEAD` alone does not
  re-stamp after a `git commit` on the current branch — `HEAD` is a *symbolic*
  ref whose contents don't change on commit; the ref it points at
  (`refs/heads/<branch>`) does. Now also watch the resolved ref (via `git
  symbolic-ref -q HEAD`) and `packed-refs`. Verified `cargo build -vv` emits
  `rerun-if-changed=.../refs/heads/<branch>`. In-image was already correct (the
  env-var path is the only source); this fixes the local `cargo run` dev loop.
- **Test hardening:** `resource_carries_vcs_revision` no longer asserts against
  the same `vcs_revision()` that produced the value (tautological); it now
  checks the attribute's *shape* (lower-hex SHA, optional `-dirty`, or the
  `unknown` sentinel) via `is_well_formed_revision`, verifying the value
  survives the `with_attribute`/`with_attributes` merge intact.
- **Dockerfile note:** documented that the `SANDBAWKS_GIT_SHA` ENV is
  builder-stage-only and does not leak into the distroless/scratch runtime
  image (flag for a future single-stage refactor).

## Out of scope

- Non-telemetry surfaces (`--version` flag, `/healthz` build-info field).
- Replacing `service.version`; the SHA is additive.
- Backfilling the SHA onto already-published images.
