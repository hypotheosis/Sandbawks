# 2026-05-22 — Plan 01 T4: `ResourceQuantity` + `ResourceRequests`

## What landed

- Added `crates/sandbawks-types/src/resources.rs`:
  - `ResourceQuantity(String)` newtype with `#[serde(transparent)]`,
    `Display`, and a `FromStr` impl that shape-validates without pulling
    in `regex`. Accepts the K8s lexical grammar
    `^[0-9]+(\.[0-9]+)?[a-zA-Z]*$` and rejects empty/garbage strings as
    `Error::InvalidQuantity`.
  - `ResourceRequests { cpu, memory, ephemeral_storage }` with
    `#[serde(rename_all = "camelCase")]` so YAML round-trips through
    `ephemeralStorage` per spec §4.1. `ephemeral_storage` is `Option`
    and `skip_serializing_if = "Option::is_none"` to keep payloads tidy
    when callers don't specify it.
  - Both types derive `JsonSchema` (CRD schemas come later in the plan)
    and `Serialize`/`Deserialize`.
- Added `crates/sandbawks-types/tests/resources.rs` with the six tests
  from the plan: `parse_plain_integer`, `parse_memory_gibibytes`,
  `parse_millicores`, `parse_rejects_empty`, `parse_rejects_garbage`,
  `resource_requests_yaml_roundtrip`.
- Wired the module into `crates/sandbawks-types/src/lib.rs`:
  `pub mod resources;` + `pub use resources::{ResourceQuantity, ResourceRequests};`.

## Why a lexical newtype (not a numeric type)

Kubernetes' quantity strings carry units that don't survive a float
round-trip cleanly — `"1.5Gi"`, `"1500m"`, `"100Mi"` all decompose to
ratios of binary/decimal SI prefixes that the API server already knows
how to normalize. Storing the verbatim string here means:

- no precision loss on suffixes the user wrote out,
- no need to bring in a heavyweight quantity parser,
- server-side normalization stays authoritative — we only enforce shape.
